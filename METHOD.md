# METHOD

The pipeline as it stands, precise enough to reimplement. Every number this
document references lives in `results/` and is regenerated by
`scripts/reproduce.sh`.

## Data

- Corpus: APTI printed Arabic word images, 2,000 PNG+TXT pairs under
  `data/apti/` (not committed; per-file SHA-256 committed in
  `manifests/manifest_apti.json`).
- Splits (deterministic function of sorted filenames + seed 20260901):
  golden 50 (regression, never tuned on), dev 200 (all tuning), held-out
  1,750 (scored once, after every decision was frozen).

## Normalization — version 1.1.0 (`src/moocr/normalization.py`)

Order of operations (the order is load-bearing; see commit history for the
verified defect the original order caused):

1. strip invisibles: U+200C/200D/200E/200F/061C/FEFF/200B/2060/00AD
2. strip tatweel (U+0640)
3. NFKC (folds presentation forms U+FB50–U+FEFF)
4. profile-dependent rules
5. whitespace collapse
6. final NFC (idempotence guarantee)

Two profiles, applied to different things:

| rule | SCORING_V1 (metrics only) | OUTPUT_V1 (delivered text) |
|---|---|---|
| strip diacritics U+064B–0652, U+0670 | yes | **no** |
| alef unification أإآٱ→ا | yes | **no** |
| ة→ه, ى→ي | yes | **no** |
| Arabic-Indic digits →ASCII | yes | **no** |

Scoring normalization is applied symmetrically to reference and hypothesis.
Every result file records `norm_version`.

## Metrics (`src/moocr/metrics.py`)

- CER: Levenshtein / reference length. Corpus CER (primary) = Σedits/Σref-chars;
  macro CER and exact-match secondary. Reported on raw AND normalized text.
- WER: suppressed on this corpus (single-word references) with the reason
  stated in every result file.
- Paired bootstrap (10,000 resamples, seed 20260901) on corpus-CER deltas;
  no unpaired comparisons anywhere.
- Bidi check: count of samples whose reversed hypothesis scores better
  (0 across all runs — visual-order storage ruled out).
- Failures: scored as CER 1.0 AND counted separately; both aggregates
  reported.

## Recognizers

| engine | checkpoint | decoding | confidence signal |
|---|---|---|---|
| easyocr | EasyOCR 1.7 `ar` model | default CTC | mean region confidence (measured r≈0.09 with correctness — never used for routing) |
| qwen_vl | Qwen/Qwen2-VL-2B-Instruct, fp16, MPS | greedy, max 64 new tokens, verbatim-transcription Arabic prompt (`config.py`), min 64·28·28 / max 640·28·28 pixels | exp(mean token logprob), r≈0.48 |
| trocr | pluggable VisionEncoderDecoder (beam 4) | — | exp(length-normalized beam score) |

TrOCR: four community Arabic checkpoints screened; none competitive on
printed APTI (`results/trocr_checkpoint_screen.json`) — engine present,
not in the evaluated configuration.

Multi-region EasyOCR output is joined in RTL reading order: lines formed by
vertical-interval overlap ≥50% of the smaller height against a running
median band interval; right edge descending within a line.

## Arbitration (`src/moocr/fusion.py`)

```
candidate = qwen_vl(image)
if degenerate(candidate.text) or candidate.confidence < 0.40:
    candidate = easyocr(image)
```

`degenerate(text)` (ground-truth-free): len(text) > 30, or ≥2 non-Arabic
letters. Thresholds chosen on dev (0 false alarms on correct output, 49/49
dev catastrophes caught). τ=0.40 chosen on dev as the centre of the flat
optimum (0.35–0.45) of `results/policy_sweep_dev.json`.

## Post-correction (CamelBERT)

`CAMeL-Lab/bert-base-arabic-camelbert-mix` as a gated reranker: candidates
are confusion-family substitutions (i'jam dot groups measured in the error
analysis) within edit distance ≤2, capped at 200; a candidate replaces the
original only if masked-LM pseudo-log-likelihood exceeds the original by a
margin. Enabled in the final configuration ONLY if net-positive on dev with
CI excluding zero — see RESULTS.md for the measured fix/break outcome.

## Visual-order (bidi) repair — `src/moocr/bidi.py`

Qwen2-VL emits full-page Arabic in VISUAL order (each rendered line
character-reversed, line order kept). A ground-truth-free detector scores
both readings of the whole output using orthographic asymmetries ("ال/لل"
word-initial, "ة" word-final and near-impossible word-initially, suffixes
"ون/ين/ات/ها") and reverses every Arabic line only when the reversed
reading wins by a margin. Replayed over all 2,000 stored evaluation
predictions: 0 outputs changed — provably inert on the evaluated domain.

## Page engine — `src/moocr/models/page.py`

For multi-line images: EasyOCR detects and reads regions; each region crop
(pad x 4%, y 20%) is re-read by the primary VLM and its text is used only
when it passes the degeneration flag (length limit scaled by the fallback
text length, max(30, 2.5x)) and a confidence bar (0.40 for word-length
regions per the dev sweep; 0.70 for line-length regions — a QUALITATIVE
default, unevaluated, see LIMITATIONS). Lines join in RTL band order,
bands join with newlines.

## Structuring (LayoutLMv3)

`microsoft/layoutlmv3-base`, `apply_ocr=False` (its internal OCR can never
run), consuming our recognizers' words+boxes. Integrated, smoke-tested,
unevaluated (no labeled data — see LIMITATIONS.md).

## Reproduction

`scripts/reproduce.sh` — reruns tests, verifies the manifest reproduces
bit-for-bit (split-drift guard), regenerates every baseline and the error
budget. Seeds: split 20260901, bootstrap 20260901. Known nondeterminism:
none observed on CPU/MPS inference for the evaluated engines (greedy/CTC
decoding); EasyOCR detector is deterministic on identical input.
